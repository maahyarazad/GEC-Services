# Quickstart: Validate the filter-panel leak fix

Manual validation guide (no automated frontend test harness exists in this project). It proves the behaviour
contract in [contracts/filter-panel-lifecycle.md](./contracts/filter-panel-lifecycle.md) and invariant INV-1 in
[data-model.md](./data-model.md). The fix is a change inside `GridToolbar` in
`public/src/components/CustomDataGrid.jsx`; see [plan.md](./plan.md) / [research.md](./research.md) for the
approach. Implementation steps live in `tasks.md` (generated by `/speckit-tasks`).

## Prerequisites

- Node/npm installed; backend and frontend dependencies already installed.
- Ability to sign in to the app and reach the **WhatsApp** dashboard (the clearest place grids live inside
  sliders).

## Run the app

```bash
# Frontend dev server (hot reload)
cd public
npm run dev
# open the printed localhost URL, sign in, go to the WhatsApp dashboard
```

(Alternatively build + serve: `cd public && npm run build`, then run the Express server from the repo root and
open the served app.)

## Static gates (must pass)

```bash
cd public
npm run lint
npm run check:compiler
```

Expected: both succeed with no new errors attributable to `CustomDataGrid.jsx`.

## Scenario A — slider close removes the panel (C-1, C-2) — PRIMARY

Use a grid that stays mounted when hidden (strongest repro): **WhatsApp → Contact Book** (also valid: Unsubscribed,
Guest List, Event Logs).

1. Open the **Contact Book** slider.
2. Click **Filters** in the grid toolbar; confirm the Filters panel appears.
3. (Optional) In DevTools Elements, confirm a floating `Paper` is a **direct child of `<body>`**.
4. Close the slider with the **× button**.
   - **Expected**: the Filters panel disappears immediately; no floating panel remains anywhere; the `<body>`-level
     node from step 3 is gone.
5. Repeat steps 1–3, then close via **backdrop click** → same expected result.
6. Repeat steps 1–3, then close via **Escape** → same expected result.

**Before the fix**: after step 4/5/6 the Filters panel stays visible, floating over the dashboard, intercepting
clicks.

## Scenario B — switching sliders (C-1)

1. Open **Contact Book**, open **Filters**.
2. Without closing it, open a different slider (e.g. **Guest List**) from the dashboard.
   - **Expected**: Contact Book's Filters panel is gone; no orphaned panel overlaps Guest List.

## Scenario C — conditionally-unmounted grid stays correct (C-1)

Use **WhatsApp → Delivery Logs** (grid is conditionally rendered, so it truly unmounts on close).

1. Open **Delivery Logs**, open **Filters**, close the slider by any affordance.
   - **Expected**: no orphaned panel (this path was already correct via React unmount; confirm no regression).

## Scenario D — inline grid non-regression (C-3, C-4, C-5)

Use any page that renders a grid directly (not in a slider), e.g. a Section grid.

1. Open **Filters**; the panel opens under the button.
2. Change column/operator via the dropdowns inside the panel.
   - **Expected**: dropdowns work; the panel does **not** close when a dropdown opens (C-5).
3. Add/edit a filter value; confirm rows filter as before.
4. Scroll the surrounding content a little, keeping the toolbar on screen.
   - **Expected**: the panel stays open and stays anchored to the Filters button.
5. Press **Escape**, then reopen and click the panel's **×**.
   - **Expected**: both close the panel (C-4).

## Scenario E — reopen is clean (C-6)

1. In any slider: open Filters, close the slider, reopen the same slider.
   - **Expected**: grid shows with Filters **closed**; no stale panel reappears.

## Pass criteria

- Scenarios A, B, C, E: **zero** filter-panel nodes under `<body>` once the grid is not visible (SC-001, SC-002).
- Scenario D: inline filtering and anchoring behave exactly as before the change (SC-003).
- No call sites were modified (SC-004); static gates pass (SC-005).
